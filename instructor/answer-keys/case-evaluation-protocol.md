# Case-Set Instructor Protocol

> **INSTRUCTOR ONLY.** Selection, rotation, and record-keeping for the
> three graded case sets. Student-visible rubric:
> `assessments/case-study-evaluation/case-evaluation-rubric.md`.

## Selection rules

- Pick 3 cases per set from `docs-meta/case-index.md` respecting the
  tier mix and CLO focus; **prefer cases whose paired solution files you
  have not used for classroom reveals in this section** (the classroom
  mode's solution reveal makes those cases poor evaluators).
- Avoid cases whose techniques the section's labs already graded
  (e.g., don't use a Wireshark-analysis case as Set A if Lab-02's
  practical grade lands the same week).
- Recommended pools (rotate termly):
  - **Set A:** cs-001…020 pool + easy M2 entries (cs-011, cs-017).
  - **Set B:** cs-026…045 pool; good evaluators: cs-031 (ACL), cs-034
    (ACL audit), cs-044 (cert expiry), cs-047 (cipher audit).
  - **Set C:** cs-066…075 + expert pool; good evaluators: cs-070 (alert
    economics), cs-076 (CVSS debate), cs-087 (timeline), cs-099-style
    injects for teams strong in IR.

## Administration

- 25 minutes: 5 read/plan, 15 write, 5 buffer. Closed book.
- Distribute the case file only (student tree); solution files never
  leave the instructor tree, including projector use.
- Record the exact case IDs used per section **in the table below**
  (leak prevention between sections and terms).

## Calibration

- Grade criterion 3 (mechanism accuracy) strictly — it is the
  discriminator between "right answer" and "right reasoning" (the
  rubric's core distinction).
- If >40% of a section scores ≤13 on a case, the *case* may be
  mis-selected for that week (evidence not yet taught) — record and
  adjust next term rather than inflating marks.
